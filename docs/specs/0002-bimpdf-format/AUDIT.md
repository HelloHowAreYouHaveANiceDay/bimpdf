## Highest-risk changes

1. **pdfmarkuptool export destroys the PDF-native layer, so any catalog- or XMP-based declaration does not survive PMT.**
   - `export-document.ts:94` builds a fresh `PDFDocument.create()` and copies pages into it. The catalog `/Metadata` (the pdfbim XMP), `/PageLabels`, `/Outlines`, `/AF` and any future `/Extensions` are all lost.
   - `sidecar-writer.ts:125` re-attaches producer sidecars with a bare `output.attach(bytes, name)`. That drops `/AFRelationship /Data`, `/Subtype` and `/Desc`.
   - `sidecar-writer.ts:103` reads only a flat `/Names` array, so attachments in a `/Kids` tree are silently skipped.
   - Under D5's "XMP label → /Extensions → AFRelationship" ladder, every PMT round-trip turns a declared bim.pdf back into "has an attachment called elements.json".
   - **This must be fixed before or with C2/C7/C8/C9.**
2. **pdf-cli is the de facto validator, and its checks are shallow and version-lagged.**
   - XMP detection is `bytes.Contains(…, "pdfbim")` (`bim_validate.go:398`). A new `bimpdf:` prefix fails it, and it cannot tell `version=2` from a format version.
   - The newest vendored schema is 1.12 (`bim_schema.go:15-19`), while producers ship 1.13 (`BimModel.cs:26`; fixture v84 is 1.13).
   - The `profile` field already holds "bim-pdf-1.10" / "v2" / "legacy-v1" / "unknown" (`bim_validate.go:36`), and drafter keys on it (`issue.test.mjs:75`). Reusing the word "profile" for spec profiles (D5) would collide.
3. **The current XMP is not a format declaration.**
   - `pdfbim:version` is hard-coded to `"2"` in both producers (`PdfBimPacker.cs:158`, `bim.go:158`). It means "PDF-BIM v2 packaging" (`bim.go:32`), not the 1.x format.
   - The namespace `http://pdfbim.com/ns/1.0/` 301s to `https://bimpdf.com/ns/1.0/`, which returns **404** (checked 2026-11-20).
   - Producers must keep writing it (D5). New readers must not treat it as the format version.
4. **The schema URL contract is pinned byte-for-byte in four places.**
   - bimpdf-site deploy polls every `/schema/*` hash (`ci.yml:132-139`). revit-cli fetches and compares (`check-vendored-schema.mjs:28`). The addin's B7 falls back to the URL (`validate-with-core.mjs:215`). pdf-cli's CI compares against `bimpdf.com/schema/$(basename)` (`.github/workflows/ci.yml:66`).
   - The old `bim-pdf-1.X.schema.json` URLs and bytes must stay frozen forever. A new spec layout has to be additive: new paths, and new `$id`s only for new versions.
5. **Five producers write at five different versions.** The addin writes 1.13. pdf-cli `package` writes 1.10. revit-cli writes 1.10. blender-cli writes 1.0 (literal). autocad-cli writes the legacy pre-1.0 wrapper. PMT readers accept any 1.x (major-only check, `formatVersion.ts`). A "2.0" or refuse-on-mismatch rule (SDLC "pin + refuse") would break blender and autocad outright, and everything else on the next bump.
6. **Public prose contradicts the direction.**
   - `bimpdf-site/index.html:130` says "no format extension, no PDF structure modification". `:205,227` say to read by attachment name only.
   - `llms.txt:38` calls **v1.1** "current"; the real current version is 1.13.
   - `bim-cli/src/bim-pdf-format.md:108` promises "PDF/A-3 embedding conventions" that are not written anywhere (and `/spec` is 404).
7. **Private data in fixtures** (see Fixtures). In particular `pdfmarkuptool/apps/pdfmarkuptool/src/test/fixtures/sample.pdf` is a real residential project ("a client project", project 26_01).

## Facts that change the design

- **The PDF-native constructs Revit gives us for free are already present.** Every Revit-sourced fixture has `/PageLabels` + `/Outlines` (probe: v84, v70, vl, v3, pmt-fixture, landing, fixture-a). C2 is "specify and preserve", not "produce". The work is in PMT export (Risk 1) and in producers that build PDFs from scratch (blender, pdf-lib fixtures).
- **Nothing writes `/VP`/`/Measure`, `/StructTreeRoot`/`/MarkInfo`, `/Extensions`, annotation `/NM`, per-page or per-annotation `/AF`, or `/Desc` on any attachment.** Of 13 probed files, 0 have any of these. All 300+ annotations have no `/NM`. C1, C4, C5, C7 and C9's `/Desc` are greenfield.
- **OCGs already exist on two writers:** blender-cli (`bim_blender_bridge.py:2700`) and PMT markup layers (`ocg-writer.ts:78-117`, with a `pmt-layers.json` sidecar too). Neither Revit fixture has OCGs.
- **AF plumbing is half there.**
  - Producers write catalog `/AF` + `/AFRelationship /Data` (`PdfBimPacker.cs:124,150`; `bim.go:147,156`).
  - pdf-lib writers (PMT export, `make-bim-fixture.mjs`) write `/Desc` + `/AF` but **no** AFRelationship (probe: sample-bim, sample-3d, coords).
  - Drafter already uses `/Supplement` for its own files (`issue.mjs:480`).
  - So "AFRelationship + /Desc on every attachment" is two small producer patches plus the PMT fix. The relationship vocabulary (Data vs Supplement vs Source) has one existing precedent to respect.
- **pdf-cli's embedded-file `/Subtype` is malformed.** It is a string on the Filespec (`bim.go:148`) instead of a MIME name on the EmbeddedFile stream. Probe: the landing sample shows `Subtype=None` on every stream. PDF/A-3 needs the stream `/Subtype`, `/Params /ModDate`, `/UF` and an XMP extension schema for custom properties. None of the producers are PDF/A-3 today: no `pdfaid` in any probed XMP, and the PDF headers are 1.6/1.7.
- **No producer output declares PDF/A-3, while PMT export also drops XMP.** PDF/A as a profile is a producer feature plus a PMT-export feature, not a schema change.
- **Detection today is by name and shape, not by declaration.** PMT uses `elements.json` (`loadBimPackage.ts:102`). pdf-cli uses elements.json shape (`bim_validate.go:455`). The PMT functions explode by extension allowlist (contract `document.objects.blobs.exts`). Sheetbench's measured agent discovery came from README-agent + the visible notice (`v1.0/build_notice_arm.py:54`; `v0/stage0b/score_stage0b.py:3`). Every D5 rung above "notice" is new reader work. No existing reader would use it.
- **Sidecar names are an open set.** PMT writes `pmt-marks.json`, `pmt-layers.json` and `pmt-export.json` (`sidecar-writer.ts:15-22`) and reserves `marks.json` with a legacy-array carve-out (`:36`). The format has 9 canonical names (`bim_schema.go` `sidecarSchemaDefinitions`) plus `README-agent.md` and `model_*.glb`. A spec needs a reserved namespace for app-private attachments.
- **`/PMT` is an unprefixed private key on annotations** (`annotation-writer.ts:395`). Under Annex E it needs a registered developer prefix (C7). Today it is the only private PDF key we write. The addin's font resource `/BimPdfNoticeHelvetica` is a resource name, which is fine.
- **README-agent.md is not a unique name.** `gh search code` finds unrelated public repos using `README-agent.md` (e.g. blaiszik/scion, receptron/graphai). An attachment name alone is a weak marker.
- **There are no external dependents.** `gh search code` for `pdfbim.com/ns` and `bimpdf.com/schema` hits only our org. `@bim-pdf/core` is **not on npm** (E404). Release-asset downloads: pdf-cli 217 total across all releases, bim-pdf-addin 4. The add-in is mainly distributed as `bimpdf-site/downloads/bim-pdf-addin.zip` (1.49 MB, committed), and its download count was not measured (Cloudflare analytics not checked). There are no internal consumers of `pdfbim.com/ns` beyond the two producers, one validator and their tests. **We can still change anything except the live schema bytes.**
- **We own `pdfbim.com`.** It redirects to bimpdf.com. Publishing a page at `bimpdf.com/ns/1.0/` makes the legacy namespace URI resolve at zero cost, which satisfies D5's "URI resolves to the spec" for the old label too.
- **Version counts:** 14 sidecar schema versions are live (1.0-1.13), plus `review-firestore.schema.json`, `context-bundle.v1.json` (drafter) and the review contracts, all under `bimpdf.com/schema/`. CONTEXT's "11 versions" is stale. Non-format contracts share the `/schema/` namespace, so the public spec must say which files are the format.
- **The stale sheetbench enum from the card body no longer exists.** The hand-rolled `tests/stages/00-schema.ts` lived in pdfmarkuptool, not sheetbench. It was replaced by the core validator (#277, decision `docs/decisions/0015`) and then deleted (#492). `pdf-bim/AGENTS.md` still documents `pnpm benchmark --stage 0`, which no longer exists. Doc drift only.
